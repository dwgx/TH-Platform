# THP-WIRE-20261002 — room.tsx and group.tsx now read from the API

**Verdict: ok.**

Both pages loaded from `api/client.ts` through `useAsync`. The module-level sample
arrays are gone. A dead backend now renders a named failure surface with a retry
button instead of an empty list that looks like "no data".

---

## 1. What changed

### `src/pages/room.tsx`

Deleted `SEATS`, `SPECTATORS`, `ROOM_CHAT`.

One `useAsync` fetcher issues all four room routes together — they are one room,
so splitting them would let the header and the seat grid render from different
responses:

```tsx
const { data, isLoading, refetch } = useAsync(async () => {
  const [room, seats, spectators, chat] = await Promise.all([
    api.getRoom(id),
    api.getRoomSeats(id),
    api.getRoomSpectators(id),
    api.getRoomChat(id),
  ]);
  return { room, seats, spectators, chat };
}, [id]);
```

Server values now drive: the sidebar title and `#id · taken/total`, the info card
(难度 / 模式 / 区域 / 可见性), the 队伍 roster and its ready count, the seat grid,
the spectator strip and its `+N` overflow, the top bar (title, `kind · gameId`,
host, ping, `taken/total`, visibility action), `ParamPanel` difficulty / mode /
RTT, the bottom-bar last-message preview and ready count, and the chat drawer
including its 对局信息 log — which is now the room's real `kind: 'sys'` lines
rather than a hardcoded five-line imitation sitting next to the real chat.

Empty seats now render as invite cards, matching the server, which returns every
slot with a null name. `+N` is computed instead of the literal `+12`.

### `src/pages/group.tsx`

Deleted `GROUP`, `CATS`, `ANNOUNCEMENT`, `GROUP_MSGS`, and the unused local
`RoomShareEmbed` (the shared `SHARED.ServerCardFlat` already renders `m.share`
and already carries UiAudit's fluid-width fix).

```tsx
const { data: head, isLoading, refetch } = useAsync(async () => {
  const [group, cats] = await Promise.all([
    api.getGroup(handle),
    api.listGroupChannels(handle),
  ]);
  const announcement = await api.getGroupAnnouncement(handle).catch(() => null);
  return { group, cats, announcement };
}, [handle]);
```

The announcement is caught to `null` because its route throws for two different
reasons — no announcement, and no server — and only the reachability probe tells
them apart. It renders as a real EmptyState inside a dashed card rather than
being silently dropped.

**Channel ids come from the server's channel list, never from concatenation.**
The page flattens the returned categories and picks the selected channel's `id`
verbatim; clicking any row re-fetches that channel's messages. Verified live:
clicking 妖妖梦 fetches `yegumi.th07`, and the header switches to it.

## 2. Three explicit states, not one

`client.ts` resolves a failed collection to `[]` and a failed room to `null`
without throwing, so "empty" and "unreachable" arrive as identical values. Both
pages therefore consult `useBackendReachable()` from
`@/components/backend-status` — the same probe lobby, dm and profile already use.
No new empty-state component: every zero-case reuses `UI.EmptyState`.

| State | room.tsx | group.tsx |
|---|---|---|
| loading | 正在读取房间… | 正在读取群组… / 正在读取消息… |
| unreachable | 读不到这个房间 + **重试** | 读不到这个群组 + **重试** |
| 404 | 房间 #N 不存在 + 返回大厅 | 群组 @h 不存在 + 返回大厅 |
| empty but real | 这个房间还没有席位 / 还没有人观战 / 还没有人说话 | 这个群组还没有频道 / 这个频道还没有消息 / 还没有置顶公告 / 这个频道还没有分享过房间 |

`BackendBanner` is on both pages, so a strip naming the outage also appears.

A subtle case I found while driving the real browser: on a **404**, the sidebar
and the drawer originally said 还没有人入座 / 还没有人说话 — "nobody has joined"
for a room that does not exist. Both pages now say 房间未载入 / 群组未载入 in that
state. Verified: `#/room/9999` and `#/group/nosuchgroup` show 未载入 in the
sidebar, drawer and aside, and the named 404 surface in the main column.

## 6. Bugs found and fixed during verification

1. **Stray avatar on embed messages.** `CMG` was rendering every message including
   `kind: 'embed'`, which carries no author — producing a "?" avatar with an empty
   body above each share card. Embeds now render the card alone.
2. **"Nobody has joined" on a 404 room.** Covered in §2.
3. Broken JSX from two of my own mid-batch edits (duplicated sidebar block,
   duplicated room-body wrapper, orphaned composer). Caught by `tsc -b` and fixed;
   the tree now parses and typechecks clean.

  store seeds rooms 1–7, so `e2e_check.ps1` screenshots a room-404 surface. That

  `PAGES` table are not mine to edit, so I left both alone.

  through the domain hooks in `@/hooks`. They are wired; the grep just does not
  see it. If the project wants one honest measure, count `use[A-Z]\w+\(` from
  `@/hooks` instead.
- **`groupStatus` / `roomStatus` are deliberately local to each page**, following
  profile.tsx's `ProfileUnavailable`. They are thin wrappers over `UI.EmptyState`
  and are not a second empty-state component.
- No new npm dependency. No vite proxy. `client.ts`, `types.ts`, `mock.ts`,
  `components/**` and `App.tsx` untouched. No commit, no push.

**No windows opened on the owner's desktop.** API and `vite preview` started with
`WindowStyle = Hidden`; Chrome headless. Ports 4173 and 8080 released; the
background stack job was stopped.
