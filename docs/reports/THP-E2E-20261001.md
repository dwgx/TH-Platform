## 二、根因：不是 profile 的锅，是浏览器够不到 API

`profile` 空白只是症状。真正的问题是**跨域被浏览器拦掉**，实测链条：

1. `src/lib/api/client.ts:76` 用绝对地址 `fetch(BASE_URL + path)`，
   `BASE_URL` 默认 `http://127.0.0.1:8080`；页面 origin 是 `127.0.0.1:4173`。
2. 修复前 `GET /v1/me` 带 `Origin: http://127.0.0.1:4173`，响应 **HTTP 200、
   body 合法，但没有 `Access-Control-Allow-Origin`**；服务端全树
   `grep -i cors` 零命中。
3. 真 headless Chrome 做同一个 fetch：`TypeError: Failed to fetch`（截图读出，
   非推断）。
4. `request()` 捕获这个 TypeError 返回 `null` → `getMe()` 抛 →
   `src/pages/profile.tsx:87` 的 `if (!me) return null` → 空白。

**为什么只有 profile 白：** 另外 5 页的数据路由失败时降级成 `[]`，照样画出完整
布局。所以 1a 那次「5/6 渲染」= 五页**空壳**。这一条已写进 `docs/README.md`
第 8 节和 `docs/verification.md`，因为它是这个项目里最容易骗过自己的验收方式。

我把这条升级给了 Main 和 UiAudit（UiAudit 当时正准备改 profile.tsx，改了也白改）。
CorsFix 车道随后落地 `server/internal/api/cors.go`，修好后实测：


### 写这个脚本时踩到并修掉的两个真 bug（不是我一开始就知道的）

1. **第一版会漏进程，还谎报「端口已释放」。** 原因是 `Get-NetTCPConnection`
   在子 pwsh 里返回了空集，于是拆除逻辑认定端口干净。实测抓到了孤儿进程：
   `thp-api.exe` pid 18604 和 node pid 31728 仍在 8080/4173 上监听，而脚本刚打印
   过 `ports released`。改成 `IPGlobalProperties::GetIPGlobalProperties()
   .GetActiveTcpListeners()`（直接读 OS 套接字表，不走 CIM），并把
   `WaitForExit` 作为「真的没了」的权威信号、端口表作为第二意见；子进程活着就
   报 WARNING 并 exit 1。
2. **缓存的 API 二进制比源码新，却不是从源码编出来的。** `%TEMP%\thp_apibin` 是
   多车道共用的，`thp-api.exe` 比最新 `.go` 新但内容是旧的，导致 CORS 检查对着
   一个源码明明允许 origin 的服务端报 `BLOCKED`。改成**每次都 build**，并且
   build 到本脚本独占的 `run-product-api.exe`。热 build 1.6 秒，没什么可省的。
   「比最新源码新」不等于「是最新的」。

## 四、`docs/README.md` 要点

10 节，全部内容都在本机跑过：

- **怎么跑 API**：注意 `config/config.yaml` 是**相对工作目录**找的，这是最常见的
  起错方式。实测 `THP_SERVER_PORT=8091` 会盖掉文件里的 8080（进程真的听 8091）。
- **怎么跑客户端**：`node node_modules\typescript\bin\tsc -b` 才是真 typecheck；
  `node_modules/.bin/tsc` 手敲会报 `%1 is not a valid Win32 application`。
- **怎么指到非 localhost 后端**：`VITE_API_BASE_URL`。**并写明了 `VITE_*` 是构建
  期内联的**——实测：用 `VITE_API_BASE_URL=http://example.invalid:9999` +
  `VITE_HANDLE=bakecheck` + `VITE_API_USE_MOCK=1` 构建，grep 产物 bundle，
  两个字符串都在里面。对着旧 `dist/` 跑 `preview` 改这些变量**静默无效**。
- **mock / 真数据切换**：默认真 HTTP；`VITE_API_USE_MOCK=1` 才走 mock。并说明三条
  路由失败会抛、四条降级 `null`、十一条降级 `[]`——决定页面长什么样。
- **验证命令**：逐条可复制。
- **两个 harness 坑**（brief 要求的重点，单独成节）：
  1. stdout 管道不排空 → 约 16 个请求后 handler 阻塞在 `logger.Info`，进程还活着，
     看起来完全像死锁；修法就是 `ReadToEndAsync()` 两行，stdout 和 stderr 都要。
  2. PS7 的 `Invoke-WebRequest` 对 4xx 的 `.value__` 是 `$null`，而且不消费 4xx 的
     body，于是**下一个**请求卡死；改用 `HttpClient` 且先排空 body。
  另附两条 Windows 专属坑（方括号路径要 `-LiteralPath`、脚本一律写 pwsh）。
