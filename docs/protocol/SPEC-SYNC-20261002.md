# 规范与实现分叉 —— 已核实

**日期**：2026-10-02
**性质**：不是 bug，是**两份真源说了不同的话**。修起来便宜，发现起来昂贵。

---

## 根子：一条信息被写在三处

| 位置 | 谁读它 |
|---|---|
| `docs/protocol/THP-PROTOCOL-v1.md` | 读文档实现的人 |
| `TH08-Platform/protocol/*.h` | 读头文件实现的人 |
| `dll/src/**` | 实际跑起来的代码 |

**三者不会自动保持一致。** 本项目这一轮已经在两处栽了。

---

## 分叉 1：状态哈希覆盖（我核实过）

**规范**（`thp_profile_th08.h:178`，即 TH08 profile 的覆盖字符串）：

```c
"activeEnemyCount(u32) activeBulletCount(u32)  <-- COUNTS ONLY, see spec 8.4\n"
```

**实现**（`dll/src/state/state_hash.h`）：

```
kLabelBulletManager / kLabelEnemyManager —— 整块区域
// 注释明确写：no activeBulletCount / activeEnemyCount anywhere
```

**问题**：`AdaptTh08` 车道把实现改成哈希整块 `BulletManager` /
`EnemyManager` 区域（弹幕的身份、位置、速度、类型都在里面），**但没有同步改
profile 头文件和规范**。

**为什么危险**：

- 对**当前代码无害** —— DLL 用 `state_hash.h`，不走 profile 头
- 对**新代码有毒** —— 任何按规范实现 TH06 / TH07 的人会原样复现 th08-multi
  那个「只比计数」的弱点，而这正是我们当初放弃它方案的原因

> 一个 bug 修完，**只有一处变了，通常意味着还有几处没变。**

## 分叉 2：构建指纹（评审发现，我核实过）

`thp_session.cpp:183`：

```c
// Build fingerprint. Until the DLL hashes the exe, this stays zero and the
// host will NOT treat it as a mismatch -- see on_hello. Claiming a
// fingerprint we did not compute would be worse than admitting we have none.
std::memset(hello.build_fingerprint.b, 0, sizeof(hello.build_fingerprint.b));
```

**全零。** 态度是对的（不虚报），但后果是 `BUILD_MISMATCH` 永不触发。

**评审指出的要害**：两台机器 `th08.exe` 完全相同、**只有我们注入的 netcode DLL
编译方式不同**（MSVC 版本、`/W4` vs `/O2`、x86 vs x64）的玩家会通过检查，然后失步。

> **指纹必须覆盖 netcode 模块本身**，因为它才是两台机器之间最可能不同的部件。

**修法**：对**我们自己的 DLL** 算指纹（不是 `th08.exe`）。成本很低。

## 分叉 3：7 条规范自相矛盾（评审 C1–C7）

> **照文档实现的实现者，和照头文件实现的实现者，会做出两个不同的协议。**

| # | 矛盾 | 后果 |
|---|---|---|
| **C1** | `START` 的方向被写了**三种**说法（§2.3 表说 host→guest；§4 生命周期图画 guest→host；§4.1 说「guest 回送给 host」）| 三条里有两条说 guest→host。按 §2.3 实现会得到一个**没有拒绝路径**的 host 发起式 START |
| **C2** | 规范说 `GAMEPLAY` 固定部分 **36**；`sizeof` 是 **40**，且 `thp_wire.h:1381` 有 `static_assert` | 4 字节误差，且恰好落在「实现者据此分配缓冲」的表里 |
| **C3** | 规范说 `0x07` 是「保留，必须传零」；它其实是 `ACK\|NAK\|FINAL` 三个活标志 | 规范把三个活标志描述成保留区 |
| **C4** | 「每帧 700 字节 @60Hz」无法从它自己的表推出（实际 ~242），且 `KEEPALIVE` 是 **1s** 不是 60Hz | 数值无害，作为预算推导会误导 |
| **C5** | `RESYNCING` **无法表示** —— `thp_resync_block` 不是 `thp_session` 的成员，`thp_session_init` 也没碰过 | §8.7 描述的状态机**存不进参考结构体**。适配器必须自己发明存储，两个适配器会发明得不一样 |
| **C6** | `ADAPTERS.md` 把「会话状态机」标为 **Done**，而同一文档 §8.7 说它无法表达 | 鉴于本项目在乐观标注上的历史，这条值得单独纠正 |
| **C7** | `thp_resync_plausible` 的注释误述自己的比较（TH06 是 `+2`，THP 是 `+4`，注释读起来像两者相同）| 低，但值得加一句 |

## 该做什么

1. **以头文件为准修规范。** 头文件有 `static_assert`、编译过、跑过；规范是散文。
2. **修 C5**：`thp_session` 加 `thp_resync_block resync;`（14 字节，不序列化）
3. **修 C6**：把 `ADAPTERS.md` 的「Done」改成实际状态
4. **指纹覆盖我们自己的 DLL**
5. **profile 头文件的覆盖字符串改成与实现一致**

**这五件事都是便宜的。** 昂贵的是下一次有人照着不一致的规范实现 TH06，
然后花几周去找一个本可以避免的分叉。
